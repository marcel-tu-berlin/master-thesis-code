2. Key Technical Concepts:
   - **Regression-as-invalidation:** in this repo a silent behaviour change invalidates results already on disk rather than breaking a feature. Measurement semantics (token counting, correctness threshold, seed mapping, budget accounting, metric definitions) are the protected surface.
   - **Environment qualification criterion (from e26):** base-model accuracy in the 40-80% band AND at least two tools. browsergym cleared it (click-option 0.50 success, click-checkboxes 0.35 success vs 0.50 termination so the axes decouple); finqa failed it (1% accuracy, no dial).
   - **`resolve_max_turns` is the load-bearing turn-cap mechanism**, not `server_env` mapping. Defined in `training/config_schema.py`; called by `grpo_runner.py:146` (→ TRL `max_tool_calling_iterations`) and `agentic_eval.py:535` (→ eval turn loop). TRL treats an unset `max_tool_calling_iterations` as `sys.maxsize`. browsergym has **no server-side step cap**, so after the deletions the `max_turns` → server-env-var mapping has zero live instances.
   - **Freezing does not resolve defaults.** `runs/<exp>/config.yaml` is a verbatim copy of the input config. A key no config states is absent from every frozen copy, so the mandated arm-matching diff reads it as "equal" when it is really "unrecorded".
   - **`DEFAULT_BATCH_SIZE = 4`, `DEFAULT_N_ROLLOUTS = 8`** in `training/config_schema.py:5-6`. Before `a19b1ff` (2026-08-06 14:17:39) the batch_size default was 1, which voided every run trained before it.
   - **"One knob differs, never two"** applies within a comparison, not across campaigns. e27/e28/e29 all run `max_steps: 300`; the bs4 poly pair runs 150. Different environments, different questions, no confound.
   - **OpenEnv server contract:** `create_app` must take `max_concurrent_envs` from `MAX_CONCURRENT_ENVS` and the env class must set `SUPPORTS_CONCURRENT_SESSIONS = True`; `reset(seed=N)` must be deterministic in N (this one fails silently — the run trains, loss moves, the advantage is noise).
   - **Tooling gotcha:** `grep` is aliased to `ugrep` in this shell. Non-ASCII checks via `grep -c '[^\x00-\x7F]'` give wrong counts — use python3. Also `grep -c "batch_size"` matches `micro_batch_size` as a substring; anchor with `^  batch_size:`.
