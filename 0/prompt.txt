2. Key Technical Concepts:
   - **The batch_size confound:** `a19b1ff` (2026-08-06) changed `grpo_runner`'s default from `t.get("batch_size", 1)` to `t.get("batch_size", 4)`. Every run before it trained at 1 prompt-group per optimizer step with 40-60% of steps carrying no gradient. A config file stating `batch_size: 4` does not mean the *run* used it — configs get edited after their runs, frozen configs in `runs/` do not.
   - **Independent verification of a run's batch size:** `train_log.json`'s `epoch` at the final step over the dataset size gives prompts per step directly (0.6 at step 300 over 500 questions = bs=1).
   - **Step-time scaling on browsergym:** 94 s/it at bs=1 (e27: 28178s/300), 712 s/it at bs=8 (e27bs8probe: 28471s/40) — ~11.4 s per completion both, so bs=4 (32 completions) ≈ 365 s/it. Actuals came in at 358 (E1), 374 (E2), 414-419 (E3).
   - **`MAX_CONCURRENT_ENVS` sizing:** `env_server.py:132-133` computes `batch_size * n_rollouts` = 32 from the shared `config_schema.DEFAULT_BATCH_SIZE = 4` / `DEFAULT_N_ROLLOUTS = 8`; the `e27bs8probe` already passed 64 concurrent sessions, so 32 is dominated.
   - **vLLM defaults:** `grpo_runner.py:35` `use_vllm = config["model"].get("use_vllm", True)`, colocate mode, util from config (0.30). Passing `--vllm` would force util 0.6 and diverge from e27 — so it is deliberately NOT passed.
   - **`--smoke` overrides:** `apply_smoke_overrides` sets max_steps 3, n_rollouts 2, max_seq ≤2048, gpu_memory_utilization ≤0.45, eval max_new_tokens 256, `_smoke=True`. It leaves `batch_size` untouched. A smoke's `hit_generation_cap` episodes and clipped_ratio do not transfer.
   - **Episode record fields:** `['correct','index','n_steps','n_tokens','reward','seed','stop_reason','terminated','tool_calls']` — the token field is `n_tokens`, not `token_count`.
   - **Eval report structure:** top-level `['experiment_id','model_slug','seed','compose_method','mode','checkpoint','smoke','results']`; `results` keyed by split; per-split metrics include `accuracy`, `accuracy_ci_low/high`, `mean_token_count_correct(_ci_low/high)`, `non_termination_rate(_ci_low/high)`, `mean_steps`, `stop_reasons`, `n_samples`, `n_correct`.
