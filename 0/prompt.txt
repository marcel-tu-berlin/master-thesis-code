2. Key Technical Concepts:
   - **GRPO per-group advantage centering** (TRL `grpo_trainer.py:2177-2199`, `scale_rewards` default `"group"`): a prompt-group whose rollouts all score alike yields exactly zero advantage; cross-group variance never reaches an advantage. Binary env_reward saturates ~46% of prompts, so batch_size=1 made ~46% of optimizer steps zero-gradient; 0.46^4 = 4.5% at batch_size 4. Cosine length reward varies within-group so it rarely saturates — the asymmetry was the confound that voided e9-e25.
   - **batch_size vs micro_batch_size:** memory is bounded by `micro_batch_size` (micro-batched forward/backward with `gradient_accumulation_steps = batch_size*n_rollouts/micro`); batch_size only grows vLLM's generation pool, which queues rather than OOMs.
