# Frozen from the GPU box venv (/workspace/master-thesis-code/.venv, Python 3.12.3,
# uv 0.9.25). setup.sh installs from this file and nothing else, so a package that
# is not pinned here does not get installed.
#
# The pins are the dependency closure of what the pipeline actually loads: `uv pip
# install -r` on this file resolves to exactly these 252 names and pulls in nothing
# extra. Packages a box venv had picked up but nothing imports (textarena, nltk,
# smolagents, the ipython tree) are not here - freezing them back in would
# resurrect dependencies this repo deleted.
#
# Regenerate after a deliberate upgrade, and only from a venv that was itself built
# from this lock, so the freeze cannot canonize whatever else got installed by hand:
#   ssh gpu-l4 'VIRTUAL_ENV=/workspace/master-thesis-code/.venv uv pip freeze' \
#     | grep -v '^-e file://' > /tmp/pins.new \
#     && grep -q '^torch==' /tmp/pins.new \
#     && { sed -n '/^#/p' requirements.lock.txt; cat /tmp/pins.new; } > /tmp/lock.new \
#     && mv /tmp/lock.new requirements.lock.txt
# The temp file and the grep are load-bearing: redirecting straight into this file
# truncates it before ssh has produced a line, so a dropped connection (see the
# NordVPN note in LAB_NOTES.md) leaves an empty lock - which then installs cleanly.
#
# openenv is installed editable from the OpenEnv clone (see setup.sh), so its
# editable line is stripped here; pipeline/OPENENV_COMMIT is its pin.
